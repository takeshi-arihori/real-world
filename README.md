# real-world

ハーネスエンジニアリングを活用した、AI時代のWeb開発フローの大まかな概要は以下の通りです。このフローは、AIが迷走しないための**「秩序（ハーネス）」を設計する準備段階**と、実際に**AIエージェントを動かす実行段階**に分けられます。

### 1. 準備段階：ハーネス（秩序）の設計
開発を始める前に、AIが従うべきルールや環境を整えます。

*   **基盤の固定**: AIと人間の共通言語として、Ruby on Railsのような規約の強いフレームワークを選定し、ディレクトリ構成や利用ライブラリを明確にします。
*   **設計・品質ルールの定義**: アーキテクチャ設計（MVC、サービスオブジェクト等）やコーディング規約を策定し、`Claude.md`や`rules`ディレクトリなどの設定ファイルに落とし込みます。
*   **ガードレールの構築**: CI（継続的インテグレーション）上でテスト、リント、セキュリティスキャン、AIコードレビューが自動で走る仕組みを作ります。
*   **ナレッジの共有（Skills）**: プロジェクト固有の作業手順や定型業務を「Skills」として登録し、AIがチームの一員として動けるようにします。

### 2. 実行段階：AIエージェントによる開発サイクル
実際のタスク（バグ修正や機能追加）は、以下のサイクルで進めます。

1.  **プランニング（設計の壁打ち）**:
    *   **プランモード（Plan Mode）**を起動し、AIに現状のコード調査と原因特定を行わせます。
    *   AIが提示した実装計画について人間が議論し、詳細な設計を固めます。
2.  **タスクのIssue化**:
    *   合意したプランに基づき、GitHub Issueを作成（または自動登録）して作業内容を明確化します。
3.  **自律的な開発実行**:
    *   AIが専用のブランチを作成し、**テスト駆動開発（TDD）**のプロセス（テスト作成 → 失敗確認 → 実装 → テスト通過）に沿ってコードを書きます。
    *   リントやフォーマットのチェックもAIが自身で実行します。
4.  **プルリクエスト（PR）の作成と検証**:
    *   AIが実装内容やテスト結果をまとめたPRを自動作成します。
    *   人間はコードを細かく読むよりも、**「仕様通りに動いているか」というクリエイティブな視点**で最終確認や微調整（バイブコーディング）を行います。
5.  **ハーネスの改善**:
    *   AIの出力にブレが生じた場合は、コードを直すのではなく、原因となった**「ハーネス（ルールや指示書）」を修正・強化**して、AIの精度を育てていきます。

このように、**「人間が道（ハーネス）を作り、AIがその上を全速力で走る」**というのが、最新の開発フローの根幹です。

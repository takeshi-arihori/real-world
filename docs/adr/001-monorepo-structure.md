# ADR-001: モノレポ構成の採用

## ステータス

承認済み

## コンテキスト

フロントエンド（React）とバックエンド（Laravel）を同一プロジェクトで開発する必要がある。リポジトリ構成としてモノレポかポリレポかを選択する必要があった。

## 決定

`web/`（フロントエンド）と `api/`（バックエンド）を同一リポジトリで管理するモノレポ構成を採用する。

## 理由

- **開発効率**: フロント・バックの変更を1つのPRで管理でき、レビューが容易
- **一貫性**: API仕様の変更とフロントの対応を同時に行える
- **チーム規模**: 小〜中規模チームではモノレポの方が運用コストが低い
- **CI/CD**: 単一リポジトリのため、CI設定がシンプル

### 代替案

- **ポリレポ**: フロント・バックを別リポジトリに分離。チームが大規模になった場合やデプロイサイクルが完全に独立する場合に検討。

## 影響

- リポジトリサイズが増大する可能性がある
- CI/CDでフロント・バックの変更検知を適切に行う必要がある
- パッケージマネージャが異なる（pnpm / composer）ため、ルートでの統一的なスクリプト管理が必要
